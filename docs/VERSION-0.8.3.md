# 0.8.3 · 通知显示与紧凑提问界面

公开版本从 v0.7.0 直接到 v0.8.3；0.8.0–0.8.2 是本机迭代，未单独公开，本次累计包含这些版本的改动。[发布页与附件](https://github.com/hc568871650-commits/codex-desktop-dual-environment/releases/tag/v0.8.3)。0.7.0 以前的版本记录仍描述各自当时的行为。

## 可用界面

- 通知页增加“待处理 / 最近完成”、连接提问服务及独立预览。普通通知可选 3、5、10、15、30 秒、自定义 1–3600 秒或常驻，动画可开关。普通提示的悬停与窗口焦点不会暂停倒计时；明确展开的选择菜单可暂时暂停。显示设置保存到控制器状态，不修改 Codex 自身偏好。
- 完成卡片使用实际窗口圆角裁切；通知来源的“返回任务”失败或任务链接不支持时显示角落反馈，不自动弹出控制面板。显示实例与准确定位任务是两项不同的验收。
- 作答窗口默认 480×380，位于屏幕工作区右下角，避开任务栏，可缩放并滚动多题；支持选项说明、自由输入、敏感输入隐藏和同问题草稿保留。它不按普通通知的倒计时自动关闭，只有明确提交才发送答案。独立预览不操作真实任务。

## 接入边界

日常 API 启动链路尚未接入提问桥接，当前真实提问仍由 Codex 原窗口处理。控制器的待处理界面、预览和“连接提问”入口不能证明真实 Desktop 问题已被接管。隔离实验验证过本机 CLI 与 Responses fixture 的问答回路及 Desktop 桥接进程加载，但真实 API Desktop 的提问、答案回传、原窗口状态同步和精确返回任务尚未完整验收；异步提问、选项选择器、审批和 MCP 表单也未逐类验收。

原生 API 通知未被全面抑制或隔离。已有用户反馈原生 ChatGPT 提问通知点击后启动官方版，因此不能用该通知作为 API 任务的可靠返回入口。桥接实验代码在源码仓库的 `experiments/notification-bridge`，其隔离运行环境和代码**不在安装包中**；发布包中的界面与预览不等于交付桥接功能。

## 验证状态

2026-09-27，最终 0.8.3 程序通过 Windows PowerShell 5.1 的 `tests/Test-All.ps1` 全部 27 套检查，包括紧凑作答窗、编译 EXE 中保存显示设置、悬停/焦点下连续计时、原生窗口圆角和通知返回。日志目录为 `test-results/validation-20260927-170403`；编译宿主通过 42 项交互检查，并确认原有 Codex 进程保留。本机安装清单内 117 个文件只读核验全部匹配。上述结果不扩大真实 Desktop 桥接的验收范围。更多历史测试记录见 [VALIDATION.md](VALIDATION.md)。

显示设置与界面细节见 [通知显示](NOTIFICATION-DISPLAY-NEXT.md) 和 [提问界面](QUESTION-UI-NEXT.md)；桥接的接入条件与剩余验收见 [API 通知接管](NOTIFICATION-BRIDGE-NEXT.md)。
