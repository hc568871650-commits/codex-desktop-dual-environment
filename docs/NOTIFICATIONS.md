# 通知、窗口标识与兼容边界

2026-09-11，本机 Store Codex 26.903.9818.0。以下结论不扩展为其他版本保证。

| 项目 | 实现/证据 | 状态 |
|---|---|---|
| 自有托盘菜单区分实例 | 单独官方/API 菜单，按进程身份定位 | 已实现、菜单渲染通过 |
| 原生托盘点击唤起哪个实例 | 本轮没有点击原生托盘，不能推断分派 | 待人工逐个测试 |
| 任务通知点击显示正确实例 | 没有发送任务，未产生用于验收的通知 | 待验证 |
| 通知跳转到正确任务 | 显示实例并不证明正确任务 ID 跳转 | 待验证，不宣称支持 |
| 恢复隐藏/最小化窗口 | EnumWindows + 进程归属 + ShowWindowAsync | 独立 WinForms 双窗口通过；真实 Codex 需逐版补验 |
| 切换前台 | SetForegroundWindow 返回值被检查，失败提示 | 真实 Codex 后台测试遭 Windows 拒绝；真实用户托盘点击待验 |
| 桌面快捷方式图标 | 工具目录内固定 O/A/D 图标 | 创建与移动后路径验证通过 |
| 原生窗口标题 | 不轮询重写标题，不把任务标题当实例 ID | 未实现标题增强 |
| 任务栏图标/分组 | 未更改 Codex 窗口 AppUserModelID、包或注册表 | 未保证区分 |

Windows 明确限制前台切换，甚至满足条件时仍可能拒绝，不能把 `ShowWindow` 返回或已找到句柄当作已获得焦点。[Microsoft：SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)

任务栏使用 AppUserModelID 关联窗口、进程和快捷方式。只给启动器换图标，不足以证明运行中的 Codex 分组会改变。外部设置窗口属性的技术可行性不等于 Codex 不会覆盖它，因此第一版不实施这类改写。[Microsoft：AppUserModelIDs](https://learn.microsoft.com/en-us/windows/win32/shell/appids)

## 后续人工验收

仅使用无重要任务的独立测试环境：分别点击两个原生托盘图标，记录当前前台窗口 PID，并与控制器身份核验结果比较。分别给两个环境发送一个极短任务，点击各自通知，独立记录“实例正确”和“任务正确”。随后测试冷启动通知、后台隐藏、多窗口和程序更新后的行为。

没有可核验的公开任务状态接口，不显示空闲、完成或运行中任务数。测试、增强均不得修改官方包或关闭安全功能。

## 当前唤起策略（preview.4）

已停用直接显示隐藏窗口。Store 版使用原生 second-instance 唤起，再聚焦可见主窗口；临时转发进程退出，原实例身份保持。用户已确认本机窗口可正常点击。非 Store 版的隐藏窗口需通过原生托盘恢复。历史记录中的 Win32 隐藏恢复测试不代表当前支持策略。
