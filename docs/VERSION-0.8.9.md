# 0.8.9 标准控制器

相对上一公开版 v0.8.8，本次标准更新聚焦退出交互、组件诊断与问答保护。下载及最终验证结果见 [v0.8.9 Release](https://github.com/hc568871650-commits/codex-desktop-dual-environment/releases/tag/v0.8.9)。

## 标准控制器

- 退出目标实例只确认一次，确认后直接结束已核验的实例；取消保留。面板内反馈，保留身份核验、当前宿主及外部进程保护。
- 修复重复打开控制器时，提前返回后清理未初始化变量的问题。
- 只读诊断展示通知、提问桥接、守护后台/CLI/托盘和自适配六项状态；不启动服务、不调用模型、不读取凭据内容。
- 桥接原因码区分 CLI 缺失、身份/哈希变化、停用等情况，保留成功对象/失败 null 的调用约定。
- 定期读取桥接新登记；待答、提交、排队结果、所有权移交、隐藏草稿或旧代理仍存在时不切换。
- 区分连接失效与确认处理，隐藏窗口继续保留未解决草稿，确认完成后才释放保护。

## 独立源码实验

标准完整包和升级包排除整个 `experiments`，不含实验代理、机器绑定、凭据和聊天。

- 自适配提问桥接：核验实际 CLI 进程链，使用空 Home 与本地 Responses fixture 验证已覆盖协议；通过后留待下次完整启动切换，失败保留原生入口。不会调用供应商模型或重启当前 Desktop。
- 原生标题建议 0.1.5：支持严格核验的 Desktop→BridgeProxy→CLI 链及局部启动器升级。不直接写数据库、不自动保存；采用后可编辑，由用户点击原生保存。生成标题会调用用户现有供应商 API。
- FirstTokenGuard 桥接兼容：独立源码与补丁，不随控制器安装，也不自动启动守护。

实验安装器仍含本机路径默认值和特定启动器模板约束，标题准备阶段仍要求直接 CLI。它们不是通用一键安装包；需要维护者审查及独立配置 Node、Python、Windows PowerShell 5.1、CLI 和控制器依赖。

## 验证与升级边界

此前标题 0.1.4 的生成和采用已有用户反馈；0.1.5 与自适配桥接在真实 Desktop 完整重启后的组合体验尚未验收。隔离测试与真实 CLI fixture 不能替代前后台操作、模型调用及保存流程验收；单个 Desktop 版本通过不代表所有版本兼容。

本轮验证记录见 [验证记录](VALIDATION.md)。标准控制器升级只需退出控制器；代理首次启用或更换所需的 Desktop 重启，应留到用户任务结束后。升级与回退方法见 [升级指南](UPGRADE.md)。
