# 0.6.2 · 已运行窗口的快速恢复

问题：最小化到任务栏后，单击API会依次全量发现实例、查询Store入口并重复做CIM身份核验。API根进程没有重启，额外发现和校验产生了接近启动的等待感。

改动只针对已经确认Running、缓存实例ID/home/profile对应、且只有一个可见主窗口的情况。快速恢复实时核对PID、创建时间、程序路径、完整命令行、profile和CODEX_HOME，持有进程句柄直到窗口归属复查完成。符合条件时直接恢复/聚焦，不进入启动器，不进行Store或全进程扫描。

缓存缺失、不一致、进程退出、隐藏到原生托盘、存在多个可见主窗口等情况继续走原路径。隐藏窗口仍必须由应用原生唤起，不强显内部浮窗。任务链接和同时打开两边的流程不变。625ms默认单双击判定保留。

## 本机测量

2026-09-26，对运行中的API进程做一次配对的最小化恢复实验：

- 原路径1081.9ms，新路径29.9ms；PID均为6848，进程身份保留。
- 数字从恢复调用开始到窗口脱离最小化状态，不包括625ms托盘单击等待，不是多轮统计或最终用户点击测速。
- 新路径这次脚本调用返回Running：窗口恢复，但Windows拒绝该次后台脚本的前台抢占；保留原有反馈语义，不能将该数字宣传为成功抢占前台耗时。
- 独立可见窗口聚焦试调用为10.9ms并返回Shown。仍需结合用户真实托盘输入体验验收。

## 实现依据与边界

复用项目已有x64 PEB读取边界，在快速恢复内只比对命令行，不输出内容。按微软说明，RTL_USER_PROCESS_PARAMETERS布局可能变化；读取失败会退回已有核验流程，不降低安全检查。
