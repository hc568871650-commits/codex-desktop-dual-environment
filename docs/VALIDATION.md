# v0.1.0 预览版验证范围

## 已验证

- Windows PowerShell 5.1：40 项核心断言，包括路径保护、中文与空格路径、TOML 转义、DPAPI 加解密、旧配置备份、API 登录模式和拒绝覆盖其他认证。
- 真实子进程：只给子进程注入指定的配置目录和密钥，父进程环境不变；官方入口清除继承的已知 API 环境变量。
- 图形窗口：实际构建 WinForms、执行环境检查按钮、渲染检查，并从解压后的分发包再次运行。
- CC Switch 3.20.0 独立实验：数据库、客户端配置、WebView 和任务数据使用独立测试目录，本机路由健康检查通过。
- 实际桌面文件测试：更换模型后，窗口显示执行命令，指定测试文件真实存在，最终内容为 `beta`。中间两次读取没有独立核实，因此只确认最终文件结果。
- 实验前后核对的 8 个既有配置/认证文件一致，既有两个 Codex 主进程仍在运行。

## 实验中发现并处理的问题

仅隔离 `CODEX_HOME` 与 Desktop profile 时，一次新窗口仍显示了原账号的界面状态。测试环境加入 `forced_login_method = "api"`、`cli_auth_credentials_store = "file"` 和独立 API 模式认证后，窗口显示 API provider，项目与聊天列表为空。

本版本将同一 API 模式约束加入生成配置，并创建非秘密占位标记 `auth.json`。真实服务商密钥仍从 DPAPI 解密后通过 provider 的 `env_key` 注入。启动前检查模式约束和标记；缺失或改变时拒绝启动。不会覆盖已有的其他登录凭据。

## 尚未证明的部分

- 上述真实文件测试使用的是 CC Switch 实验链路，不等同于最终图形分发包对所有直连服务商均已完成端到端验收。
- 不保证所有 Codex Desktop 版本都接受同样的 profile 和任务目录配置。更新后仍应重复隔离验收。
- 不保证模型名称真实对应某个底层模型，也不保证上游稳定性。一组测试中出现长等待、断流，以及回复已完成但未执行文件操作；不能仅凭这些现象归因于启动器。
- 尚未进行完整安全审计、签名认证或所有 Windows 显示缩放比例测试。

因此当前版本标记为预览版。公开包不包含实验数据库、真实密钥、OAuth、会话记录、模型调用账单或个人路径截图。
