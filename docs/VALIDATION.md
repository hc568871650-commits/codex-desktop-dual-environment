## 透明窗口遮挡修复（preview.3）

试用时发现桌面右侧和任务栏点击被 Codex 内部置顶工具窗口截获。旧窗口枚举仅看 PID、窗口类及非空标题，把内部工具窗口也列为主窗口；恢复该隐藏窗口后造成透明遮挡。此前“每实例两个窗口”的观察不能作为两个正常主窗口的证据。

仅隐藏两个已核验的 captionless/topmost/tool 窗口后，用户确认桌面和任务栏恢复正常。未终止原 Codex 进程、未重启 Explorer、未改动原配置。

修复：枚举及最终 Show/Close 前均排除 WS_EX_TOOLWINDOW 和 WS_EX_NOACTIVATE。四个真实实例现在各返回一个正常主窗口。回归夹具新增带标题的隐藏置顶工具窗口，确认不会进入恢复/关闭候选；实例套件 39 项通过。

preview.1/preview.2 存在此缺陷，不应继续使用。工作区试用快捷方式已指向修复后源码。

## 窗口可见但无法点击修复（preview.4）

透明工具窗口修复后，用户仍报告打开的正常主窗口不能点击。只读检查显示鼠标命中 Codex 渲染窗口，没有额外遮挡、鼠标捕获或菜单捕获。直接 Win32 显示不足以恢复应用交互状态是本次的工作推断，不宣称已确定 Electron 内部具体失效点。

只读检查本机安装程序发现 packaged Windows 版支持 requestSingleInstanceLock / second-instance，并从该处理路径调用自身窗口显示逻辑。分别以相同 EXE、home、profile 发送原生唤起请求，临时转发进程退出、原 PID 和创建时间不变；用户确认窗口内部按钮和输入框恢复正常。

控制器现在对动态检测到的 Store 版调用此原生入口，不携带凭据；只聚焦应用已显示的主窗口，不再使用 ShowWindow 强行显示隐藏窗口。短暂转发进程不等于新增常驻实例。非 Store 版或原生唤起未完成时，不降级强制显示。该行为需逐版本验收，不保证原生通知任务跳转。

## 任务栏入口（preview.5）

新增系统 .NET Framework 编译的 CodexDualController.exe。它在独立 GUI 进程内运行系统 PowerShell 5.1 控制逻辑，任务栏固定项指向该程序，不指向 powershell.exe。不改变 Codex 自身图标/任务栏分组。

小面板提供打开官方/API、状态刷新、分别退出和退出控制器。右上角关闭只隐藏面板到托盘。再次启动相同配置通过当前用户的命名事件显示原面板；不同配置不会混用。未设置开机自启。

本机通过 Explorer 的“固定到任务栏”菜单完成固定，并核验系统固定快捷方式的目标。实测关闭面板再调用固定入口：原控制器 PID 保持、只有一个常驻控制器、面板重新显示；两套日常 Codex 仍运行。托盘/面板/单实例三项 UI 测试、安装卸载 11 项、实例 39 项通过。

编译入口 scripts/Build-ControllerHost.ps1；已有环境部署入口 scripts/Deploy-Controller.ps1。安装/部署清单包括新增 EXE。卸载后固定在任务栏的项需用户解除固定；卸载不改写系统任务栏注册表、不删除用户数据。
