# 0.4.1：独立任务完成提示

控制器会读取两套环境中的明确任务完成事件，在屏幕角落显示独立提示卡片。“打开对应端”按实例身份找回或启动官方/API端。不会把某一端的通知统一转交另一端，也不自动发送任务。

## 显示和操作

- 单条卡片贴近屏幕工作区底部，不因官方或API身份预留空位。
- 新卡片在底部，已有卡片向上排列；关闭一条自动补位。同一环境的新完成合并到该环境卡片。
- 自动显示时不抢输入焦点；点击“打开对应端”才请求切换窗口。Windows拒绝前台切换时仍会提示，不把后台存活误报成前台切换成功。
- 卡片不展示回答正文或密钥，不进入Windows通知中心，也不提供通知历史。当前只保证进入对应端，不保证跳到具体任务。

## 开关与运行

升级后默认开启。在控制器托盘右键菜单中勾选或取消“独立任务完成提示”。首次开启跳过既有历史；控制器重启后补读尚未处理的完成记录并去重。暂停再开启采用新的起点，不补发暂停期间的旧记录。

监听在独立后台进程运行，每秒检查增量、约四秒发现新日志文件，支持跨日和旧会话继续写入。只接收Codex Desktop主任务的明确task_complete事件，过滤子代理。文件截断、替换或损坏时停用该文件，不猜测完成，也不阻止其他正常文件。运行状态在控制器state/notifications保存，不改两端配置和日志。

控制器退出时监听也停止。控制器未运行时不会显示新卡片；重启可补读未处理记录。为控制资源，监听存在文件数量和单行长度等上限，异常状态可查看state/notifications/worker-status.local.json。

## 与原生通知的区别

这是经过实际点击实验验证的控制器独立提示。原生通知的Windows包身份和旧通知均未改写。原生完成通知若仍开启，可能与新卡片重复出现；应使用独立卡片的“打开对应端”。可在两端应用设置中按需关闭原生任务完成通知。本次不会擅自改写运行中应用的通知偏好。

按用户最新安排，控制台及托盘左键优化留待单独处理。0.4.1的托盘左键仍打开控制面板；此前API直达实现保留在开发历史提交37b96d3。

用户点击实验中，API两次、官方一次均进入各自原进程；前台窗口匹配、原配置未改。正式版另有后台进程、文件发现/重启去重、界面操作与安装升级检查，详见VALIDATION.md。
